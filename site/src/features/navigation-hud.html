The layout

What is on the glass

The HUD switches to this layout by itself while Google Maps is guiding, and gives your own layout back when it stops. Nothing needs a touch, and nothing needs a decision while you drive.

  1. Your speedThe same big figure as on every HUD layout, from the OBD adapter or from the phone's GPS when there is no adapter.
  2. Google's own arrowA one-colour picture Maps puts in its notification, painted in your HUD colour. It is Google's drawing, so a hairpin or a roundabout looks the way Google drew it.
  3. Distance to the turnIn Google's units. In the last metres Maps drops it, and the HUD drops it too.
  4. The instructionGoogle's words in the phone's language, up to three lines, cut at a word.
  5. The lineA sketch of the next junction: it leans the way the arrow turns and the dot climbs as the turn comes up. It is not a map. Google gives other apps no route, so TapeDash cannot draw the road ahead.
  6. ETA, time left, distance leftAll from Maps. When it gives no time left, the HUD uses the ETA minus the phone's clock.

It always says what state it is in

The mechanism

One notification, read one way

While Google Maps guides you it keeps a navigation notification up, the one in your shade with the arrow and the street. TapeDash is allowed to read that notification, and only that one. It needs no network to do it.

Google's side

Google Maps

Plans the route, reroutes, and uses its own internet connection. Posts the turn as a notification.

Android

The notification

Title, text, sub-text and a one-colour arrow bitmap. Nothing custom, no route geometry.

TapeDash

The listener

Checks the package first and drops everything that is not Google Maps. Passes a small struct to the app.

TapeDash

The HUD

Parses it in plain Dart, holds it in memory, marks it stale when Maps goes quiet, and draws it.

Where the wall is. Everything that touches the internet is on the left of the third box. TapeDash has no socket, no HTTP client and no network class anywhere in this feature, and the build fails if one appears.

On the real phone, with real Maps

A debug build first, then the release build, installed over the existing app with adb install -r so trips, price and adapter stayed. Google Maps 26.42 on Android 16, navigating a fixed test route in Bangalore while the phone's position was faked from the shell at 30 km/h. These are the frames as the glass shows them: mirrored.

The speed is blank in them. The shell can send a position but no speed, and the OBD adapter was not plugged in, so there was nothing to show.

Three bugs the phone found, now fixed

The emulator's Maps and your phone's Maps post different shapes of notification. The first run on the phone showed three mistakes the emulator never could. Each fix has a test that was seen failing without it.

"0 M" over a straight arrow

Maps writes a distance of 0 m next to "Head east" and "towards ...". A zero distance now counts as no distance.

A sharp right read as a left bend

Maps' hairpin arrow looks like a left bend to a simple reader, so the line would have leaned the wrong way. It is now left unread and drawn straight.

"Rerouting" read as "Starting"

Maps 26.42 sends an empty sub-text with "Rerouting...". The HUD now shows the right state.

The one thing the app cannot fix

Maps' pop-up card, and the fix

As a turn nears, Google Maps moves its notification into a high-importance channel called "Navigation urgent updates", and Android drops it over the top of the screen for about six seconds. On a HUD that is a bright card over the arrow and the distance.

I first got this wrong

I had written that the card shows once, and that Do Not Disturb was the answer. Measured with the release build and real Maps, it shows at about every turn and Do Not Disturb changes nothing. The notes in the app and the docs were corrected.

How Garage walks you through it

  1. In Garage, Navigation, tap Open Google Maps' notification settings. It opens Android's own page and does not start Maps.
  2. Open the list of categories and choose Navigation urgent updates. The name may differ in your language.
  3. Turn off Pop on screen. Leave the notification itself on, because that is what the HUD reads.
  4. Also deny Maps' floating window (Settings, Apps, Special app access, Picture-in-picture). Allowed, it puts a bright map over the HUD's corner.

Setting it up

Turning it on takes one switch and one Android screen

It is off to begin with. Turning it on says it needs notification access and opens Android's own page, where you switch TapeDash on and confirm Android's dialog. Android shows that dialog for any app with this access, and its wording is broader than what TapeDash does. Garage says plainly what TapeDash reads.

The contract

TapeDash never connects to the internet

It may read the navigation notification of a navigation app you have installed, which has its own connection. It sends that app nothing. Six rules hold that line, and tool/check_offline.sh fails the build if one is broken. Each rule has a test that was seen failing when the rule was removed.

One package

The listener checks the notification's package before it reads anything else of it. A release build allows com.google.android.apps.maps and nothing else.

One way

TapeDash reads. It never replies to the app, presses its buttons, or launches it with a destination.

Nothing kept

What it reads lives in memory, for the HUD. It is never written to a trip, a recording, the exchange file or the log. Street names are location data.

No network code

No socket, no HTTP client and no networking import in the listener or the navigation code.

Off by default

Switched on in Garage, parked only, with a plain explanation. You can revoke it in Android's settings at any time.

Stale is stale

When Maps stops updating, the HUD says so. It never shows an old turn as a live one.

One honest caveat, which Garage also states: Android does not enforce the package filter. It is a promise kept by tests and by the code being open source.

Status, 28 October 2026

What has and has not been verified

Pre-alpha  Built and tested on emulators and on one real phone with a faked position. Not yet driven in a car.

Verified

  • 3,956 tests, the offline check and the Android API 24 lint pass.
  • Android 16 emulator with real Google Maps 25.33, including the release build from a cold open.
  • Android 7.0 emulator, the minimum, with a stand-in for Maps (the real Maps cannot run there).
  • The target phone: Android 16 with Maps 26.42, the debug and then the release build, four runs of 2 to 3 minutes at 25 to 27 degrees. Turns, distances, ETA, rerouting, the card and the floating window, and the Garage row that opens Android's page.

Not yet verified

  • A real drive: the sun, heat, and a whole trip with the adapter and Maps running together.
  • The speed on the HUD on the phone. The shell cannot send a speed and the adapter was not there, so it was blank.
  • Miles and other languages. Both captures so far are English and kilometres.
  • Roundabouts, U-turns and highway exits, and Maps' progress-style notification on a phone.
  • The windshield itself: brightness, the double image of laminated glass, and whether three lines of text survive it.
  • Frame rate on an old 2 GB phone. Emulators say nothing about it.

Where it works. Only where Google Maps itself runs, on the same phone as TapeDash. Today's Maps needs Android 9 at the very least, so the 2 GB Android 7 target phone cannot run it, and there the switch is simply not offered.
