Garage

Settings that wait until you are parked

Everything you can set lives in Garage, which opens from the parked dock and closes itself when the car starts to move. Each setting changes at once and is remembered. The sensible defaults mean you rarely need it: install to live gauges in under two minutes with no manual.

Other groups hold the adapter (with a connection log that says why a connection failed, and an option to record what the adapter says), the engine sound, the navigation switch, and your data. Deleting the data needs a full slide.

The exchange file

Your data as a file you can read

Trips live in a private database on the phone, which a release build does not let a computer read, and a watch has no keyboard. So there is one file format for moving your data out and in: newline-delimited JSON, optionally gzipped, that you can read with less, grep or jq. Nothing is ever sent by TapeDash itself: no account, no server.

{"t":"tdx","v":1,"app":"tapedash", ... "scopes":["profile","trips","fillups","rest"]}
{"t":"profile","vehicle":{...},"money":{"pricePerLitre":115.0},"adapter":{...}}
{"t":"trip","startedMs":...,"distanceKm":14.2,"litres":0.93,"cost":106.9, ...}
{"t":"samples","trip":...,"cols":["s","kmh","rpm","thr","lph","lat","lon",...],"rows":[...]}
{"t":"fillup","litres":31.2,"amount":3588,"full":true,"factor":1.02}
{"t":"rest","readings":[[1792950000000,12.61]]}
{"t":"end","counts":{...},"crc32":"9be3a2f0"}
  • Checked whole first. A reader verifies the header and every byte against the footer's CRC-32 before it changes anything. A file cut short by a dropped connection or a full disk is refused whole.
  • Merged, never overwritten. Imports merge by start time and never overwrite what is already on the phone.
  • Many ways to carry it. adb, a file in the app's own folder, Android's share sheet and file picker on a phone, and the folder on a watch.
  • Tools for your laptop: tool/tdx.dart to inspect, check, merge and turn a file into CSV, and tool/adb_exchange.sh to export, pull, push and import over adb.
{{fig: design-review/watch/screenshots/15-export-message.png | The watch after an export: Exported 8 trips, 2 fill-ups, the setup. Saved in the outbox folder. | From the watch's menu. An export, saved in the outbox folder where adb can reach it.}}

Never exported: unfinished trips, simulated trips, the adapter's remembered protocol and connection log, recordings, and the running fuel count since the last full tank, which is only right on one device.

Survey drive

Ask every module what it knows

The first real drives showed that the car has two engine computers answering with different readings, and that the dashboard read only 9 of the 32 it lists. A survey drive finds out what your car will really tell TapeDash, so the next pages (an electrical page, an engine page) can be designed from what it gives and not from what a car like it might.

What it reads

  • Live data (Mode 01) as fast as the adapter allows.
  • Stored, pending and permanent fault codes (Modes 03, 07 and 0A), and the engine computers' own test results (Mode 06).
  • The calibration ID and the computers' names (Mode 09), and the adapter's own voltage reading.

What it never does

  • Write anything, clear codes or change a setting.
  • Ask for the VIN, so the file does not carry it.
  • Use the network or your location. The file stays on the phone until you copy it off.

It takes over the adapter, so the dashboard is off while it runs. A guided, parked list of steps comes first, then the drive with nothing to touch. It is in Garage, Adapter, Survey drive, and a tool on your laptop, tool/survey_summary.dart, turns the file into a summary or CSV.

Said plainly

What has been seen

Seen

  • Garage's every control, at 640, 720 and 800 wide, and the flow through the real app.
  • The exchange file's writer, reader and merge in tests, and an export and import on a Wear OS emulator, read back on a laptop with the tool.
  • The survey against a simulator with two engine computers, with each way back from an adapter that will not cooperate. A first survey file has been recorded from a real car.

Not yet

  • Android's share sheet and file picker on a phone. They compile and are tested on a mocked channel.
  • adb's reach into the app's folder on every device. It is documented Android behaviour, and has not been tried on all of them.
  • The survey's analysis. It will say which of its assumptions about the adapter held.
  • Beam, a phone-to-watch transfer over our own Bluetooth link. It is designed and not built.
